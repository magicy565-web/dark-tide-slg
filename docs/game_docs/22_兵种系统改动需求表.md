# 22_兵种系统改动需求表（全面改造版）

> 目标：把“兵种创建/升级/进阶/战斗结算/AI使用/UI反馈/存档兼容”一次性拆成可执行需求表，避免每轮只修一个点。

---

## 1. 现状问题总览

| 领域 | 当前典型问题 | 影响 |
|---|---|---|
| 创建链路 | legacy 与新内政入口历史上存在分叉，容易出现“资源扣了但实例未正确入池” | 战斗中看不到新兵、数值不同步 |
| 升级链路 | 升级规则曾分散在 `GameManager`，策略/成本/门槛不集中 | 调参困难、回归风险高 |
| 进阶门槛 | 兵种进阶与经验成长耦合弱，玩家成长曲线不清晰 | 中后期策略深度不足 |
| 编制上限 | 增援/招募在边界场景下可能出现超编风险 | 平衡被破坏，AI/玩家都可利用 |
| 战斗一致性 | 升级后 HP/属性字段若未统一重算会漂移 | 伤害计算异常、面板显示不一致 |
| UI呈现 | 玩家不总能提前看到“可升级条件/缺什么” | 误操作与挫败感 |
| AI决策 | AI 对升级/招募优先级依赖启发式，缺少“收益/成本”统一评分 | AI兵种构成质量不稳定 |
| 存档兼容 | 新增兵种字段与旧档迁移策略不统一 | 读档异常或字段缺失 |

## 3. 数据结构改动建议

### 3.1 兵种升级配置（建议新增）
- 文件：`data/troop_upgrade_rules.json`
- 建议字段：
  - `from_troop_id`
  - `to_troop_id`
  - `min_exp`
  - `cost`（gold/iron/特殊资源）
  - `requires_building`
  - `requires_faction_trait`

### 3.2 兵种实例字段（保持/补充）
- 保持：`troop_id`, `soldiers`, `max_soldiers`, `experience`, `atk`, `def`, `spd`
- 补充建议：
  - `upgrade_count`（追踪已进阶次数）
  - `last_upgrade_turn`
  - `source`（recruit/quest/event/convert）

## 4. 跨模块影响清单

| 模块 | 需要配合的改动 |
|---|---|
| `autoloads/game_manager.gd` | 只保留流程编排与事务回滚，不持有兵种策略细节 |
| `systems/combat/recruit_manager.gd` | 成为兵种创建/升级策略唯一入口 |
| `autoloads/game_data.gd` | 提供 tier cap 与兵种定义读取；避免业务逻辑内嵌 |
| `systems/combat/combat_system.gd` | 使用升级后一致字段进行战斗计算 |
| `scenes/ui/*` | 展示升级可行性、成本、经验差值、失败原因 |
| `systems/faction/*ai*.gd` | 接入升级评分逻辑，避免随机升级 |
| `save/load` | 处理新增字段与版本迁移 |
| `systems/mod/mod_manager.gd` | 支持升级链与成本配置可覆写 |
